# План реализации этапа 2: подача заготовок, обработка, выдача и складирование

Статус: план работ (реализация не начата). Базируется на инструментах этапа 1 (`demo_video/`), которые
подключаются через `stage2_logistics/tools.py`.

## 1. Цель этапа

Показать заказчику **полный цикл** участка, а не только сварку: заготовки поступают в кассете, собираются
и прихватываются, автоматически загружаются в сварочную ячейку, свариваются (существующая хореография
этапа 1), выгружаются, маркируются, проходят контроль и складируются в стеллаж готовых спулов. Результат —
демо-видео ~90 с (1080p) плюс RoboDK-станция с тем же составом оборудования и та же степень достоверности:
кинематика решена численно, коллизии проверены по всем кадрам, ничего не «проходит сквозь» детали.

Демо иллюстрирует «Решение 4» и раздел «Логистика и комплектование» из предложения: один комплект деталей
на один спул, кассеты для отводов и фланцев, V-образные ложементы, отдельная зона загрузки ячейки.

## 2. Сценарий материального потока

```
 [1] Кассета заготовок          [2] Сборочно-прихваточный   [3] Буфер входа       [4] Сварочная ячейка
     фланец + отвод + труба  ->     стенд (фиксация, зазор,  ->  рольганг с V-        (этап 1: робот +
     на паллете / в кассете         прихватка роботом)           ложементами          2-осевой позиционер)
                                                                                           |
 [7] Стеллаж готовых спулов    [6] Маркировка + контроль   [5] Выгрузка          <-------- |
     (или кассета на AGV)   <-     (ID спула, лазерный     <-  (робот-погрузчик /
                                    скан шва, охлаждение)       портал)
```

Ключевые решения сценария (обсуждаются с заказчиком, см. §7):

* Сборка и прихватка выполняются **до** сварочной ячейки на отдельном стенде — это прямо следует из вывода
  предложения («до покупки робота стабилизировать подготовку кромок, сборку и логистику») и снимает с
  дорогой ячейки ручные проблемы сборки.
* Перемещение спула между постами выполняет **робот-погрузчик с клещевым захватом** (базовый вариант) либо
  портальный манипулятор (альтернатива). Оба варианта закладываются в план, выбор — по данным заказчика о
  массе и габаритах.
* Складирование — стеллаж с V-ложементами у ограждения плюс опциональный AGV, который увозит кассету
  готовых спулов (показывается кратко, как «следующий шаг»).

## 3. Варианты компоновки подачи и выдачи

| Вариант | Состав | Плюсы | Минусы | Когда выбирать |
|---|---|---|---|---|
| A. Робот-погрузчик | 2-й робот (класс IRB 6700 / KR 210, 2.6–3.2 м) на пьедестале между входным буфером, позиционером и выходом; клещевой захват для труб DN100–300 | Гибкость по номенклатуре, один манипулятор на загрузку/выгрузку/подачу на стенд, эффектно в демо | Отдельная зона безопасности, захват под каждый диаметр (сменные губки) | Масса спула ≤ 250–300 кг, много типоразмеров |
| B. Портальный манипулятор | Портал над ячейкой с осями X/Y/Z и поворотом, захват | Большая грузоподъёмность, простая траектория, не занимает пол | Меньше выразительности, дороже монтаж, конфликт с вытяжкой и краном | Тяжёлые спулы > 300 кг |
| C. Рольганги + позиционер с самозажимным патроном | Спул подаётся рольгангом в патрон, робот только варит | Минимум оборудования | Плохо для отводов и разветвлений, не решает выдачу | Прямые трубы и короткие спулы |

Рекомендация для демо: **вариант A** (робот-погрузчик), с закладкой замены на портал без переделки
хореографии сварки (интерфейс «передача детали в позиционер» одинаков).

## 4. Рекомендуемая компоновка (расширение `cell/layout.py`)

Система координат этапа 1 сохраняется: позиционер в начале координат, трек сварочного робота вдоль Y на
x = 2.0, планшайба при сварке смотрит на +Y. Новые зоны (координаты в метрах, предварительные):

| Зона | Положение | Состав |
|---|---|---|
| Кассета заготовок | x = −6.5…−4.5, y = −1.5…1.5, за пределами ограждения на стороне загрузки (−X) | Паллет-кассета 1200×1600 с гнёздами: отводы, фланцы; рядом стойка с трубами в V-ложементах |
| Сборочно-прихваточный стенд | x ≈ −4.0, y ≈ 2.5 | Стол с призмами, упорами, регулируемыми ложементами; пневмоприжимы; передвижная стойка с прихваточной горелкой (робот-погрузчик держит деталь или отдельный малый робот) |
| Робот-погрузчик | пьедестал x ≈ −3.2, y ≈ 0.0, высота 0.6 | Робот 2.6–3.2 м, клещевой захват с поворотным модулем, датчики положения губок |
| Буфер входа | x ≈ −4.2, y ≈ −0.5…−2.5 | Рольганг 2 м с V-ложементами, 2 позиции, датчик наличия |
| Ворота загрузки в ограждении | сторона −X (уже есть проём со световой завесой) | Световая завеса переключается в режим muting при проходе робота-погрузчика; либо рольганг проходит сквозь ограждение под защитным тоннелем |
| Выходной конвейер | x ≈ −2.8…−6.0, y ≈ −2.9 | Рольганг/цепной транспортёр к посту контроля |
| Пост маркировки и контроля | x ≈ −6.5, y ≈ −2.9 | Лазерный/струйный маркировщик ID спула; сканер профиля шва на стойке; зона охлаждения |
| Стеллаж готовых | x ≈ −8…−9, y = −3…3 | 2–3 яруса V-ложементов; опционально AGV-кассета у торца |

Правило безопасности (для достоверности): зона робота-погрузчика и зона сварочной ячейки разделены
ограждением с передачей детали через позиционер только когда сварочный робот в транзитной позе; ни один
манипулятор не входит в чужую зону. Это же правило станет проверкой в коде (§6.8).

## 5. Хореография этапа 2 (черновой таймлайн)

Итоговое видео ≈ 90 с при 24 fps (≈ 2160 кадров). Сварочная часть этапа 1 (46 с) ускоряется до ~30 с
монтажом (сектора 3–4 показываются коротко), чтобы уложить логистику.

| № | Кадры (≈) | Действие | Камеры |
|---|---|---|---|
| 1 | 1–120 | Общий план участка: кассета, стенд, робот-погрузчик, ячейка, выход, стеллаж. Титул | широкий план сверху, медленный проезд |
| 2 | 121–330 | Робот-погрузчик берёт трубу из кассеты → на стенд; берёт отвод → стыкует к трубе по упорам; берёт фланец → к отводу. Прижимы зажимают | средний план стенда, крупный план захвата |
| 3 | 331–450 | Прихватка: прихваточная горелка ставит 4 прихватки на каждый стык (короткие вспышки дуги, искры) | крупный план |
| 4 | 451–560 | Робот-погрузчик снимает собранный спул, переносит через проём к позиционеру (тот в позиции загрузки, планшайба вверх), ставит фланцем на планшайбу, зажимы фиксируют, захват отпускает и уходит; световая завеса «зелёная» | план с −X, план от позиционера |
| 5 | 561–1280 | Сварка — хореография этапа 1 в сжатой форме (лазерный поиск, шов A, переезд, шов B сектора 1–2, индексация, сектора 3–4 коротко) | камеры этапа 1 |
| 6 | 1281–1400 | Сварочный робот в транзитной позе, позиционер в позицию выгрузки; робот-погрузчик забирает спул | план с −X |
| 7 | 1401–1520 | Спул на выходной рольганг → пост маркировки: маркировщик наносит ID, сканер проходит по швам (лазерная линия), индикатор «OK» | крупный план маркировки, план сканера |
| 8 | 1521–1700 | Робот-погрузчик (или рольганг + перекладчик) укладывает спул в стеллаж; параллельно берёт следующую трубу из кассеты — показать, что цикл непрерывный | средний план стеллажа, затем общий |
| 9 | 1701–1900 | AGV подъезжает к стеллажу/кассете готовых, забирает кассету (опционально, если заказчик хочет) | широкий план |

Подписи (русские) продолжают стиль этапа 1: тег + текст; звук: сервоприводы, пневматика прижимов,
прихватки, дуга, маркировщик, рольганг.

## 6. Технические работы (по модулям)

Все новые модули лежат в `stage2_logistics/` и импортируют этап 1 через `tools.py`. Ничего в
`demo_video/cell` не переписывается; расширения делаются наследованием/оборачиванием, чтобы этап 1
оставался воспроизводимым.

### 6.1 Компоновка и данные
* `layout2.py` — константы новых зон (§4), поверх `cell.layout`. Расширить keep-clear-зоны для окружения.
* `parts.py` — номенклатура заготовок для демо: труба, отвод, фланец как отдельные объекты (сейчас `spool.build()`
  делает единый спул; нужно вынести построение частей в отдельные функции с единым локальным фреймом, чтобы
  части можно было носить по отдельности и «собирать» в спул без пересборки геометрии).
* Данные заказчика (§7) — параметризация диаметров/длин через `layout2`.

### 6.2 Оборудование (геометрия)
* `handler_robot.py` — второй робот. Меши: доступен только IRB 4600 (URDF из `compas_fab`). Варианты:
  (a) использовать тот же IRB 4600 на пьедестале как погрузчик (честно для спулов до 40 кг, для демо
  допустимо с оговоркой); (b) процедурно масштабировать звенья до пропорций IRB 6700 (2.6 м); (c) запросить
  у заказчика/интегратора STEP модели нужного робота. Кинематика — тот же `robot_urdf.URDFArm` + IK.
* `gripper.py` — клещевой захват: две поворотные губки с призмами под DN100–300, поворотный модуль,
  датчики; анимация раскрытия/закрытия (два шарнира).
* `cassette.py` — паллет-кассета с гнёздами (отводы, фланцы), стойка труб с V-ложементами.
* `assembly_station.py` — стенд с призмами, упорами, пневмоприжимами (анимация штоков), прихваточная
  горелка на стойке (или малый робот), датчик зазора.
* `conveyor.py` — рольганги (входной буфер, выходной), ролики с анимацией вращения, V-ложементы, упоры.
* `marking_qc.py` — маркировщик (голова, эмиссивный «лазер» + появление надписи-декали с ID на трубе), сканер
  профиля шва (переиспользовать `vfx.laser_line` с проекцией на поверхность), световой индикатор.
* `storage.py` — стеллаж с ярусами V-ложементов, уже лежащие готовые спулы, опционально AGV (платформа,
  колёса, маяк) на простой траектории.
* Дополнение `environment` — расширить пол/ограждение/разметку под новые зоны; не трогая `cell/environment.py`,
  добавить `environment2.py`, который вызывает `environment.build()` и дострaивает.

### 6.3 Хореография
* `animation2.py` — мультимашинный планировщик: единый список событий (frame, машина, действие) вместо
  вложенных диапазонов; «передача детали» реализуется сменой родителя объекта в кадре захвата/отпускания
  (`matrix_parent_inverse` фиксируется на кадре, чтобы деталь не «прыгала»).
* Переиспользование `animation.build()` этапа 1 для сварочной части со сдвигом кадров (добавить параметр
  `frame_offset` и хуки «позиция загрузки/выгрузки» — минимальная правка этапа 1, обратно совместимая).
* IK для робота-погрузчика: 6-DoF (ориентация захвата важна) — `robot_urdf.ik` без `free_spin`, с
  проверкой пределов; траектории переноса — Cartesian через промежуточные точки над препятствиями.
* Захват/сборка: последовательность «подход → закрытие губок → подъём → перенос → опускание → открытие»
  как параметризованный шаблон `pick_place(part, from_pose, to_pose)`.
* Прихватка: 4 коротких интервала дуги на стык с использованием `vfx.build` (уже поддерживает список
  интервалов) на отдельном arc-empty прихваточной горелки.

### 6.4 Камеры и монтаж
* `cameras2.py` — новые планы (§5); правила из критики этапа 1: камеры над ограждением или внутри зоны,
  вне зоны качания детали и траекторий захвата; не резать кадр в момент перекрытия объектива.
* `post/storyboard2.json` — подписи, интервалы дуги/сервоприводов/пневматики; `compose.py` используется без
  изменений (параметр `--storyboard`).

### 6.5 Эффекты
* Дополнить `vfx`: искры прихватки (короткие), «лазер» маркировщика, вспышка сканера; всё через уже
  существующие функции с новыми константами. Дым — только при прихватке и сварке.

### 6.6 RoboDK
* Расширить `demo_video/robodk/build_station.py` вторым роботом (из библиотеки RoboDK: IRB 6700 или
  аналог), захватом (инструмент), рольгангами/стендом/стеллажом как объектами, программами Pick/Place,
  общим `DemoCycle2`. Механизмы конвейеров — 1-осевые `BuildMechanism`. Проверка — mock Robolink, как в
  этапе 1.

### 6.7 Рендер
* Видео 90 с ≈ 2160 кадров при ~35 с/кадр (1080p, настройки этапа 1) ≈ 21 ч на этой машине. Мероприятия:
  (1) рендер по сценам с разным качеством (широкие планы 6 сэмплов, крупные 8); (2) сварочную часть
  переиспользовать из готовых кадров этапа 1 там, где камера и хореография совпадают (сдвиг кадров), это
  экономит ~30 %; (3) параллельные воркеры по чанкам с возобновлением (`render_final.sh`); (4) при наличии
  GPU-машины у заказчика — тот же `build.py` считает в разы быстрее.
* Превью каждой сцены (каждый 6–12-й кадр, 640×360) и критика перед финальным рендером — как в этапе 1.

### 6.8 Проверки
* `tests/t_collision2.py` — расширить проверку: два робота + деталь в захвате + стенд + рольганги + стеллаж
  (полилинии/капсулы для новых объектов), правило разделения зон (§4).
* Достижимость: тест всех точек захвата/укладки для робота-погрузчика по образцу `t_ik_layout2.py`.
* Непрерывность: максимальный шаг сустава на кадр, отсутствие рывков при смене родителя детали.
* Тайминг: сверка интервалов раскадровки с фактическими событиями (дуга, прижимы, конвейер).

## 7. Что нужно от заказчика (входные данные)

1. Номенклатура спулов для демо: диаметры, длины, масса (труба, отвод, фланец), 2–3 типовых изделия.
2. Как поступают заготовки: кассеты/паллеты, размеры, число мест; хранение труб (стойка, длины).
3. Где выполняется сборка/прихватка сейчас и допустимо ли выделить отдельный стенд; ручная или автоматическая
   прихватка.
4. Грузоподъёмность и тип средств перемещения (кран, погрузчик, AGV), проходы, площадь под участок.
5. Требования к маркировке (формат ID, способ: краска, лазер, бирка) и контролю (визуальный, лазерный
   профиль, УЗК на отдельном посту).
6. Такт/сменность: сколько спулов в смену — для показателей на финальной карточке.
7. Предпочтительные производители (робот-погрузчик, захват, конвейеры) — для выбора моделей в RoboDK.

Пока данных нет — план использует допущения: спул DN250 этапа 1 (~60 кг), робот-погрузчик по кинематике
IRB 4600 с пометкой «класс 150–200 кг», кассета 1200×1600, стеллаж 3 яруса.

## 8. Риски и допущения

* **Меши второго робота** — в контейнере доступен только IRB 4600; для точного внешнего вида IRB 6700 / KR 210
  нужны модели от заказчика или доступ к RoboDK-библиотеке (там они есть, и RoboDK-часть не пострадает).
* **Реалистичность захвата отводов**: клещевой захват под трубу и под отвод отличаются — в демо один захват со
  сменными губками; в ТКП нужно уточнять.
* **Передача детали в позиционер**: требуется зажимное приспособление на планшайбе (быстрозажимные кулачки
  вместо болтов этапа 1) — добавить в геометрию позиционера (небольшая правка `positioner.py`, совместимая).
* **Время рендера** — см. 6.7; при 21 ч без GPU нужен план рендера по сценам и запас времени.
* **Длина видео**: 90 с — верхняя граница внимания; если заказчик хочет короче, сцены 3 и 9 сокращаются.

| 8. RoboDK | второй робот, захват, конвейеры, `DemoCycle2`, mock-тесты, README | 2, 4 | 2–3 |
| 9. Документация и передача | README подпроекта, инструкции по перерендеру, список допущений | 7, 8 | 1 |

Итого ≈ 20–24 чел.-дня плюс машинное время рендера. Критический путь: 1 → 2 → 3 → 4 → 5 → 7.

## 10. Критерии приёмки

* Видео 1080p ≥ 24 fps, 75–90 с, с русскими подписями и звуком; полный цикл §2 показан без разрывов.
* Численно подтверждено: IK без отказов, шаг сустава ≤ 6°/кадр, зазоры робот–деталь–оборудование ≥ 0 во всех
  кадрах, зоны роботов не пересекаются во времени.
* Каждая единица оборудования из §4 присутствует в компоновке и в RoboDK-станции; RoboDK-скрипт проходит
  mock-тесты и `py_compile`.
* Финальная карточка содержит поток §2 и показатели (такт, число постов, тип захвата).
* Репозиторий: `stage2_logistics/` собирается одной командой (`build2.py --preview`), README описывает
  входные данные и допущения.
