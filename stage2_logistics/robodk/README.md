# Полный цикл участка (этап 2) в RoboDK

Скрипт `build_station2.py` строит в RoboDK станцию **`PipeSpool_FullCycle`**: сварочную ячейку этапа 1
(ABB IRB 4600 на треке + 2-осевой позиционер + хореография сварки `DemoCycle`) и зону логистики этапа 2
на стороне загрузки (−X). В зоне логистики работают робот-погрузчик ABB IRB 6700-150/3.20 на линейном треке
с клещевым захватом и прихваточный робот ABB IRB 1600-6/1.45. Кроме них в станции есть кассета заготовок,
буфер труб, сборочный стенд, выходной рольганг с паллетой-спутником, арка маркировки и контроля,
ступенчатый стеллаж, ограждение зоны и AGV. Главная программа **`DemoCycle2`** проходит весь цикл из
видео этапа 2: комплектация → прихватка → загрузка в позиционер → сварка (`DemoCycle` этапа 1) → выгрузка →
рольганг и контроль → стеллаж.

Скрипт этапа 1 `demo_video/robodk/build_station.py` **не изменяется**. Он импортируется как библиотека,
и из него берутся функции построения ячейки, геометрии (`box_tris`, `cylinder_tris`, `write_stl`),
программ и видов.

## Что нужно

* **RoboDK 5.6.5 или новее**, как для этапа 1: `AddShape` с несколькими цветными телами и `AddCurve` требуют
  сборку 23742+. `CloseStation` и `setActiveStation` нужны только для замены уже открытой станции; в старых
  сборках станция просто добавляется ещё раз.
* Три робота в локальной библиотеке RoboDK. Их можно загрузить так: *File > Open online library* → найти модель
  → *Download*.

  | Роль | Модель | Шаблон поиска файла (`PATH_LIBRARY`, рекурсивно) |
  |---|---|---|
  | сварочный (этап 1) | ABB IRB 4600-40/2.55 | `*IRB*4600*40*2.55*.robot` |
  | погрузчик | **ABB IRB 6700-150/3.20** | `*IRB*6700*150*3.20*.robot`, …, `*IRB*6700*.robot` |
  | прихваточный | **ABB IRB 1600-6/1.45** (или IRB 1520ID) | `*IRB*1600*6*1.45*.robot`, …, `*IRB*1520*ID*.robot`, `*IRB*1600*.robot` |

  Если файл не найден, скрипт выведет путь к библиотеке и откроет диалог выбора `.robot`, как в этапе 1.
* Python-пакет `robodk`. Он входит в комплект RoboDK; для внешнего python: `pip install robodk`.
  Blender (`bpy`) и `numpy` для построения станции **не нужны**.
* Файлы репозитория, которые читает скрипт:
  * `demo_video/robodk/build_station.py` — функции этапа 1;
  * `demo_video/cell/layout.py` и `stage2_logistics/layout2.py` — все координаты;
  * `stage2_logistics/cameras2.py` — виды камер этапа 2 (файл читается через `ast`, без `bpy`);
  * `stage2_logistics/robodk/plan2_robodk.json` — снимок плана, см. ниже.

## Как запустить

Вариант 1 — из RoboDK: `File > Open` → выбрать `build_station2.py` → правой кнопкой → *Run Python script*.

Вариант 2 — из терминала при запущенном RoboDK:

    cd stage2_logistics/robodk
    python build_station2.py

Скрипт создаёт станцию `PipeSpool_FullCycle`, сохраняет её в `PipeSpool_FullCycle.rdk` рядом со скриптом и
выводит список проблем, если какие-то цели недостижимы. После этого запустите программу **`DemoCycle2`**.
Чтобы записать видео, используйте *Tools > Record*.

Флаги в начале скрипта:

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `SAVE_RDK` | `True` | сохранить `.rdk` рядом со скриптом |
| `REPLACE_OPEN_STATION` | `True` | закрыть уже открытую станцию с тем же именем без сохранения, чтобы повторный запуск пересобирал станцию, а не плодил копии |
| `REFRESH_PLAN` | `False` | перед сборкой пересчитать снимок плана (только в python этапа 2 с `bpy`/`numpy`) |
| `ADD_CURVE_FOLLOW` | `True` | проекты «curve follow» швов из этапа 1 |
| `USE_VIEWS` | `True` | макросы видов `View2_*` из `cameras2.py` и их вызовы в программах |

Флаги этапа 1 (`OPEN_2D_CAMERAS`, `MECH_GEOMETRY_IN_BASE_FRAME` и др.) не надо менять в файле этапа 1. Их можно
переопределить в `build_station2.py` перед вызовом `build()`, например `B.OPEN_2D_CAMERAS = True`.
Во время сборки служебные файлы этапа 1 (`torch.stl`, `ArcOn/ArcOff`, `View_*`) пишутся в
`stage2_logistics/robodk/generated/`, а не в `demo_video/`.

### Снимок плана `plan2_robodk.json`

Цели строятся из тех же кадров, что использует `plan2.py`: `station_frame()`, `carrier_frame(x)`,
`grasp_frame(name)`, `spool_on_positioner(0, POS_LOAD_ROT)`, `layout2.storage_frame`, кадры кассеты и буфера.
Скрипт пересчитывает их из `layout2.py` средствами `robomath` (мм). Тест проверяет, что они совпадают с
numpy-функциями `plan2`.

Часть данных требует окружения этапа 2 (`bpy`, `numpy`), и поэтому хранится в снимке:

* суставы погрузчика `handler_q` и положение каретки в событиях хореографии;
* планируемые позы TCP в этих событиях;
* позы горелки и суставы прихваточного робота для прихваток.

После изменения `plan2.py` или `layout2.py` снимок нужно обновить:

    cd stage2_logistics
    python3 robodk/build_station2.py --export-plan          # из кэша plan2 (out/plan2_<hash>.npz)
    python3 robodk/build_station2.py --export-plan --fresh  # пересчитать план

Если снимка нет, станция всё равно строится: цели номинальные, начальные приближения IK — домашние суставы.

## Что создаётся

| Элемент | Описание (мм, мировая СК этапа 1: позиционер в начале координат) |
|---|---|
| ячейка этапа 1 | окружение, трек Y + IRB 4600, горелка `MIG torch`, позиционер (наклон + планшайба), камеры `Cam_*`, программы этапа 1 (`DemoCycle`, `Cell_Home`, `Robot_*`, `Track_*`, `Pos_*`). Цельный спул этапа 1 **не** ставится |
| `Faceplate spool frame` | система координат на планшайбе в кадре спула (30 мм над планшайбой); на ней кривые швов `Seam A/B curve` и `Clamp studs` (прижимные шпильки, видимы только в зажатом состоянии) |
| `Logistics` | система координат зоны логистики (совпадает с мировой): в ней все цели этапа 2 и неподвижные детали |
| `Handler track X` | механизм 1T вдоль X (станина + каретка). Значение оси — мировая x оси J1: ход −8300…−3100 (`HANDLER_TRACK_X`), дом −6400, верх каретки z = 550, yaw 0 |
| `ABB IRB 6700-150/3.20` | погрузчик; его база сидит на каретке трека |
| `Tong gripper` | клещевой захват: STL из коробок и цилиндров (переходная плита, поворотный модуль, корпус, губки с V-призмами, пневмоцилиндры), TCP = Tz(420) — ось захватываемой трубы |
| `ABB IRB 1600-6/1.45` + `Tack torch` | прихваточный робот на пьедестале (−3200, 2450, 400), yaw 180°, с горелкой MIG этапа 1 |
| `Output conveyor` + `Carrier pallet X` | рольганг (неподвижное звено) и паллета-спутник (механизм 1T вдоль X). Значение оси — x центра фланца: −7500…−4200 (загрузка −4200, контроль −6000, конец −7500). На паллете едет `Carrier spool frame` |
| `Part flange`, `Part elbow`, `Part pipe`, `Part flange 2` | детали DN250: фланец Ø405 × 28 со ступицей до шва A, отвод R381 (90°), труба Ø273,1 × 9,3, длина 600. Кадр каждой детали — кадр собранного спула (правило `layout2`); в начале детали лежат в кассете и буфере |
| статические объекты | `Kit pallet` (паллета, кассета, гнёзда фланцев и отводов), `Pipe buffer`, `Assembly station` (стол, посадочное кольцо, V-блоки, упор, прижимы, датчик зазора), `Tack pedestal` (+ источник), `QC arch`, `Storage rack` (2 яруса + заполненные места `Stored spool T*B*`), `Logistics fence` (проёмы, световые завесы, лампы muting), `AGV`, `Logistics floor`, `Kit elbow 2`, `Buffer pipe 2/3` |
| макросы (`generated/*.py`) | `GripperClose`, `GripperOpen`, `StudsUp`, `StudsDown`, `TackArcOn`, `TackArcOff`, `ArcOn`/`ArcOff` (имена этапа 1, валик наносится на отвод), `ResetParts`, `QC_MarkScan`, `View_*` (кадры этапа 1), `View2_*` (кадры этапа 2) |

### Как ведут себя детали

* `GripperClose` берёт деталь, у которой точка хвата (`layout2.GRASP`) ближе 40 мм к TCP захвата. Вместе с ней
  берутся все детали с тем же кадром: у собранного спула фланец, отвод и труба лежат в одном кадре.
* `GripperOpen` отдаёт деталь держателю по положению кадра детали:
  * планшайба (`Faceplate spool frame`) — дальше деталь едет с позиционером через всю сварку;
  * паллета-спутник (`Carrier spool frame`) — деталь едет с рольгангом;
  * `Logistics` — во всех остальных местах.

  Если деталь оказалась в пределах 15 мм и 3° от номинального гнезда (стенд, стеллаж, кассета, буфер,
  планшайба, паллета), она ставится в гнездо точно. Так следующий хват совпадает без накопления погрешности.
* `ResetParts` (вызывается из `Cycle2_Home`) возвращает детали в кассету и буфер, опускает шпильки и стирает
  следы валиков. Поэтому `DemoCycle2` можно запускать повторно.

## Программы и соответствие сценам видео

Для погрузчика есть шаблоны Pick/Place:
1. каретка едет к нужной x (`HTrack_*`);
2. TCP выходит в высоту переноса 1550 мм над точкой;
3. подход над точкой: +250 мм (фланец, труба, паллета), +300 мм (отвод, конец рольганга, стеллаж), +350 мм
   (собранный спул на стенде) — те же высоты, что в `plan2`;
4. линейно вниз;
5. `GripperClose` или `GripperOpen`;
6. линейно вверх.

Декартовы цели хранят решение IK, найденное вблизи суставов из плана. Так сохраняются конфигурации из видео:
J1 = ±90° у стенда и рольганга, J1 ≈ −165° у стеллажа.

| Сцена (PLAN.md §5 / кадр `cameras2.py`) | События `plan2` | Программы RoboDK |
|---|---|---|
| 1. Общий план (`S2_01_wide`) | `start` | `Cycle2_Home` (+ `ResetParts`, всё в дом, планшайба 180°) |
| 2. Комплектация стенда (`S2_02_flange`, `S2_03_elbow`, `S2_04_pipe`) | `kit_flange_grip` … `gap_ok` | `KitFlange`, `KitElbow`, `KitPipe`. Погрузчик затем ждёт у стенда (`Wait_Station`) |
| 3. Прихватка (`S2_05_tackA`) | `tack_start` … `tack_home` | `TackWeld`: 6 прихваток (A0–A2 на шве A, B0–B2 на шве B). Для каждой: MoveJ в точку в 70 мм по оси горелки, MoveL к шву, `TackArcOn`, пауза 0,4 с, `TackArcOff`, MoveL назад. Затем `Tack_Home` |
| 4. Перенос и загрузка (`S2_07_pick`, `S2_08_load`, `S2_09_ready`) | `stn_spool_grip` … `ready` | `PickTackedSpool` (разжать, взять спул за трубу, поднять на 2,3 м). `LoadPositioner`: пре-позиция снаружи ограждения при каретке x = −4800 (TCP x = −3400), muting, каретка на −3100 (TCP идёт по прямой вдоль +X), линейный вход, опускание на планшайбу (наклон 0, поворот 180°: труба к −X), `StudsUp`, `GripperOpen`, выход тем же путём. Затем `Handler_Park` |
| 5. Сварка (кадры этапа 1 `View_C1…C9`) | `weld_first` … `weld_last` | `DemoCycle` этапа 1 без изменений. Его `Cell_Home` поворачивает планшайбу 180° → −20°, как в видео |
| 6. Выгрузка (`S2_10_done`, `S2_11_unload`) | `tilt_home` … `handler_out2` | `Pos_RotUnload` (360° → 540°: труба снова к −X), `UnloadPositioner` (`GripperClose`, `StudsDown`) |
| 7. Рольганг, маркировка, контроль (`S2_12_carrier`, `S2_14_mark`, `S2_15_scan`) | `conv_load_contact` … `at_end` | `ToConveyor`. `Conveyor_QC`: `Conv_ToQC`, `QC_MarkScan` + сигналы `LaserMarker`/`ProfileScan`/`QCTower`, затем `Conv_ToEnd` |
| 8. Следующий комплект и склад (`S2_16_store`) | `kit_flange2_grip` … `handler_home_end` | `KitFlange2` (фланец 2 на стенд), `StoreSpool` (с конца рольганга в место (0, 2) стеллажа), `Handler_Home` |
| 9–10. AGV, финал (`S2_17_final`) | `agv_arrive`, `end` | только вид; AGV — статичный объект |

Вспомогательные программы:

* `HTrack_<место>` — каретка погрузчика: `Home`, `KitA`, `KitB`, `Buffer`, `Station`, `Wait`, `Swing`,
  `Positioner`, `Idle`, `ConvLoad`, `ConvEnd`, `Storage`;
* `Conv_ToLoad`, `Conv_ToQC`, `Conv_ToEnd` — паллета-спутник;
* `Pos_RotLoad`, `Pos_RotUnload` — планшайба;
* `Tack_Home` — прихваточный робот в дом.

Сигналы `setDO` в программах (`GripperClosed`, `StationClamp*`, `GapOK`, `LightCurtainMuting`, `TackArc`,
`LaserMarker`, `ProfileScan`, `QCTower`) — имена для постпроцессора. В симуляции они ничего не двигают.

## Проверки

    python3 stage2_logistics/tests/t_robodk2.py

Нужен пакет `robodk`. Проверки согласованности с `plan2` требуют `numpy` и `bpy`, как остальные тесты
этапа 2; без них эти проверки пропускаются.

Что проверяет тест:

* `py_compile` скрипта и всех сгенерированных макросов;
* пересчёт единиц м ↔ мм, рад ↔ град и поз туда и обратно;
* равенство 36 кадров функциям `plan2`;
* совпадение целей с позами TCP плана в событиях: ≤ 5 мм и ≤ 1°;
* досягаемость всех декартовых целей: центр запястья не дальше номинального вылета от оси J1 на высоте плеча
  (IRB 6700: 3200 мм, IRB 1600: 1450 мм);
* все x каретки лежат в пределах хода трека;
* полная сборка на mock-Robolink (mock этапа 1 из `demo_video/tests/t_robodk_math.py`, дополненный абсолютными
  позами через механизмы): крепления баз и систем координат, состав объектов, программ и макросов, порядок
  `DemoCycle2`;
* сборка в «python RoboDK» без `bpy`/`numpy` (отдельный процесс), сборка без снимка и повторная сборка;
* **симуляция `DemoCycle2`**:
  * программы проходятся по вызовам, механизмы двигают каретку, паллету и позиционер;
  * сгенерированные макросы `GripperClose`/`GripperOpen`/`ResetParts`/`Studs*` **исполняются** на маленьком
    симуляторе деталей;
  * каждая цель погрузчика должна вызываться при правильной x каретки;
  * в конце спул должен оказаться в месте (0, 2) стеллажа, а фланец 2 — на стенде.

## Ограничения и допущения

* **Модели роботов отличаются от видео.** В Blender погрузчик и прихваточный робот — это масштабированный URDF
  IRB 4600 (×1,25 и ×0,57, `kin.scaled_arm`); в RoboDK — библиотечные IRB 6700-150/3.20 и IRB 1600-6/1.45.
  У них другие длины звеньев: у IRB 6700 плечо 780 мм, звенья 1280 и 1592,5 мм; у масштабированного IRB 4600 —
  619, 1369 и 1588 мм. Поэтому:
  * позы TCP те же, что в видео, а углы суставов и силуэт руки отличаются;
  * суставы из плана используются только как начальное приближение IK, чтобы сохранить конфигурацию;
  * проверка по сфере досягаемости — необходимое, но не достаточное условие. Окончательно решает IK RoboDK:
    недостижимые цели перечисляются в консоли после сборки.
* **Прихватка B0.** В текущем снимке (`plan_hash` da4c235321e4) `plan2` не нашёл IK для прихватки B0 на
  масштабированной руке (`ik_fail` в снимке). Для неё берётся номинальная поза, подобранная тем же перебором,
  что в `plan2`: угол 80° вместо 90°, центр запястья ≤ 97 % вылета IRB 1600. Максимальный вылет среди целей
  прихватки — 1394 из 1450 мм, то есть робот работает почти на пределе. Пьедестал стоит проверить на реальном
  IRB 1600: сдвинуть к стенду или поднять.
* **Каретка и рука движутся по очереди.** Каретка ездит в подпрограммах `HTrack_*`, а синхронизация внешней оси
  RoboDK не используется. В видео вход в ячейку — совмещённое движение. Путь TCP тот же (прямая вдоль X), тайминг
  другой. Скорости номинальные (1000 мм/с перенос, 250 мм/с подход, трек 1000 мм/с, рольганг 450 мм/с), и
  хронометраж RoboDK не совпадает с кадрами видео.
* Программы погрузчика не проверяются через `Update()`: каретка движется вызовами подпрограмм, которые `Update()`
  не исполняет. Проверяются сварочные программы и `TackWeld`. Столкновения не проверяются (`COLLISION_OFF`).
* **Упрощённая геометрия:**
  * оборудование собрано из коробок и цилиндров;
  * губки захвата неподвижны (сомкнуты);
  * прижимы стенда, каретка арки контроля и AGV не двигаются;
  * паллета-спутник одна;
  * прижимные шпильки показаны видимостью объекта, а шесть болтов планшайбы этапа 1 остаются на месте (этап 1
    не меняется).
* **Следы валиков.** Сварочные пистолеты (`Spray_Add`) существуют только в текущем сеансе RoboDK, а их номера
  хранятся в параметрах станции `ARC_GUN_ID`/`TACK_GUN_ID`. Если станцию сохранили после прогона цикла, то после
  повторного открытия удалите эти параметры, иначе следы валиков не появятся.
* **Поиск по именам.** Макросы находят объекты по имени (`RDK.Item`). Перед запуском цикла закройте другие
  станции с такими же именами, например станцию этапа 1 `PipeSpool_WeldCell`, и не переименовывайте детали и
  инструменты.
