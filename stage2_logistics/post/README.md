# post/ — пост-продакшн видео этапа 2

Собирает итоговый ролик этапа 2 (1920×1080, 24 fps, 2154 кадра = 89,75 с при текущем EDL) из **новых
планов этапа 2** (PNG-кадры сцены Blender) и **отрезков готового видео этапа 1**
(`demo_video/deliverables/demo_welding_cell_1080p.mp4`), которые вставляются без повторного рендера.
Поверх частей этапа 2 накладываются титры в стиле этапа 1, звук синтезируется заново для всего ролика.

Модули этапа 1 (`demo_video/post/overlays.py`, `audio.py`) **импортируются, а не копируются**: титульная
плашка, нижние подписи и угловая метка рисуются теми же функциями, звук дуги/сервоприводов/фона — теми же
синтезаторами, поэтому стиль совпадает с этапом 1 один в один.

```
post/edl.json          монтажный лист (генерирует ../edl.py; здесь только читается)
post/storyboard2.py    генератор раскадровки: edl.json + тексты -> storyboard2.json (кадры ВЫХОДНОГО ролика)
post/storyboard2.json  раскадровка в формате этапа 1 + поля этапа 2 (генерируется, руками не править)
post/overlays2.py      финальная карточка этапа 2 (схема потока из 7 шагов) + сборка всех оверлеев
post/audio2.py         саундтрек: слои этапа 1 + прихватка, пневматика, рольганг, маркер, сканер, AGV, сигнал OK
post/compose2.py       CLI: кадры этапа 2 + видео этапа 1 + оверлеи + звук -> mp4 (ffmpeg)
tests/t_post2.py       тест на синтетических кадрах (см. ниже)
```

## Монтаж по EDL

`edl.json` перечисляет сегменты в порядке выхода; кадры выходного ролика нумеруются с 1:

* `{"src": "s2", "shot", "f0", "f1", "out0", "out1", "caption"}` — кадры сцены этапа 2 `f0…f1`
  (номера кадров Blender, файлы `frame_NNNN.png`) показываются как выходные кадры `out0…out1`;
* `{"src": "s1", "f0", "f1", "out0", "out1"}` — кадры `f0…f1` видео этапа 1 (1-based).

Текущий монтаж:

| выход | источник | содержание |
|---|---|---|
| 1–736 | этап 2, планы S2_01…S2_09 | общий план, комплектация, сборка, прихватка, перенос, загрузка ячейки |
| 737–1096 | этап 1, кадры 97–456 | подготовка, лазерный поиск, шов A |
| 1097–1486 | этап 1, кадры 541–930 | шов B, индексация 180°, секторы 3–4 |
| 1487–2154 | этап 2, планы S2_10…S2_17 | выгрузка, рольганг, маркировка, контроль, стеллаж, AGV, финал |

Склейки непрерывны по времени сцены (кадр сцены = `weld_offset` + кадр этапа 1), поэтому робот, позиционер
и спул по обе стороны склейки в одном состоянии. На кадрах склеек (97, 456, 541, 930 этапа 1) вшитых подписей
этапа 1 нет: титр этапа 1 кончается на 96-м кадре, ни одна подпись этапа 1 не разрезана монтажом, а до
ближайших подписей этапа 2 не меньше 4 кадров (проверяет `storyboard2.check`). Угловая метка «ДЕМО ·
СИМУЛЯЦИЯ · УСКОРЕНО» у этапа 1 вшита в то же место и с той же непрозрачностью — на склейке она не мигает.

Как собирается видео (`compose2.py`, один проход ffmpeg, без промежуточных кодирований):

1. **Блок этапа 2** (подряд идущие сегменты s2) — список ffconcat, по строке на каждый выходной кадр →
   PNG нужного кадра сцены; `setpts=N` (ровно 24 fps) → `scale=1920:1080:flags=lanczos` → yuv444p →
   оверлеи → yuv420p. Если кадр сцены не отрендерен, берётся ближайший отрендеренный кадр ≤ него **внутри
   того же плана**, а если такого нет — первый после него. Поэтому работают разреженные превью (каждый 6-й
   кадр, 640×360); для финального рендера недостающие кадры выводятся как `WARNING`.
2. **Сегмент этапа 1** — видео этапа 1 декодируется и режется по номерам кадров
   `trim=start_frame=f0-1:end_frame=f1`, `setpts=N`; кадры идут в кодер без изменений (оверлеев на них нет:
   титры этапа 1 уже вшиты). Точность проверяется: `--verify` / тест сравнивают первый и последний кадр
   каждого сегмента с кадрами f0/f1 этапа 1 (PSNR ≈ 43–48 дБ, соседние кадры 11–37 дБ — склейки попадают
   точно в кадр).
3. `concat` всех частей → libx264 crf 18 (preset medium, с `--preview` — veryfast), yuv420p,
   `+faststart`; звук AAC 192 кбит/с. `--compact` добавляет второй выход из того же графа: crf 25,
   preset slow, AAC 128 кбит/с (как компактная версия этапа 1).

## Запуск

```bash
# из корня репозитория (относительные пути ищутся в текущей папке, затем в stage2_logistics/)
python3 stage2_logistics/post/storyboard2.py                    # edl.json -> storyboard2.json (после правки текстов/EDL)
python3 stage2_logistics/post/compose2.py --frames stage2_logistics/out/frames \
        --out stage2_logistics/out/stage2_final.mp4 --compact stage2_logistics/out/stage2_final_compact.mp4 --verify
python3 stage2_logistics/post/compose2.py --frames stage2_logistics/out/preview_frames \
        --out stage2_logistics/out/stage2_preview.mp4 --preview    # разреженные кадры 640×360
python3 stage2_logistics/post/audio2.py --out stage2_logistics/out/soundtrack2.wav --report   # только звук
python3 stage2_logistics/tests/t_post2.py                        # тест (~2–3 мин)
```

Параметры `compose2.py`:

| ключ | назначение |
|---|---|
| `--frames DIR` | папка с `frame_NNNN.png` этапа 2; номер = кадр **сцены** (не выходного ролика) |
| `--out FILE` | выходной mp4 |
| `--edl FILE` | монтажный лист (по умолчанию `post/edl.json`) |
| `--storyboard FILE` | раскадровка (по умолчанию `post/storyboard2.json`; если файла нет — строится из EDL в памяти; раскадровка от другого EDL отвергается) |
| `--stage1 FILE` | видео этапа 1 (по умолчанию `stage1_video` из edl.json) |
| `--preview` | быстрый пресет x264; разреженные/маленькие кадры ожидаемы, без предупреждения |
| `--no-audio` | без звуковой дорожки |
| `--compact FILE` | дополнительно компактная версия (crf 25, slow, AAC 128k) |
| `--keep-temp` | сохранить PNG оверлеев, списки ffconcat, WAV и команду ffmpeg в `<out>_tmp/` |
| `--verify` | после кодирования проверить склейки с этапом 1 (PSNR ≥ 30 дБ и лучше соседних кадров) |
| `--soundtrack WAV` | взять готовый WAV вместо синтеза |
| `--threads N` | потоки x264 (0 = авто) |
| `-v` | подробный вывод ffmpeg |

Временные файлы создаются в системной временной папке (`tempfile`) и удаляются. Нужны только Python 3.8+
(numpy, Pillow) и `ffmpeg`/`ffprobe` в `PATH`; символьные ссылки не используются — работает и в Windows.
Если шрифт из раскадровки (Linux-путь DejaVu) не найден, `overlays2.resolve_font` ищет DejaVu в обычных
папках шрифтов и в matplotlib, затем Arial / Segoe UI (все с кириллицей).

## Как менять подписи, титул, финальную карточку

Все тексты и правила таймингов — в начале `storyboard2.py` (`TITLE`, `CAPTIONS`, `END_CARD`, `FOOTER`,
`CORNER_LABEL`); после правки запустить `python3 stage2_logistics/post/storyboard2.py`. `storyboard2.json`
не редактируется руками — тест проверяет, что он совпадает с результатом генератора.

* **Подпись** привязана к плану ключом `caption` в `edl.json` (он приходит из `cameras2.py`). Ключ → `tag`
  (оранжевый чип, автоматически в верхнем регистре) и `text` (перенос по словам, ширина ≤ 1160 px, строки
  выравниваются). Новый ключ в `cameras2.py` требует записи в `CAPTIONS`.
* **Тайминги** (в выходных кадрах): титул — с 1-го кадра до `out1` первого плана − 10; подпись — с
  `out0 + 3` своего плана до «границы» − 4, где граница — последний кадр серии следующих за ним планов без
  подписи, но не дальше следующего сегмента этапа 1 и кадра перед финальной карточкой; финальная карточка —
  последние 100 кадров (`END_CARD_FRAMES`). Над сегментами этапа 1 ничего не рисуется. Проверки
  (`storyboard2.check`): нет пересечений, промежутки ≥ 4 кадров, подпись ≥ 28 кадров, каждый оверлей длиннее
  двух фейдов (12 кадров; у карточки 14), всё внутри блоков этапа 2.
* **Угловая метка** — по одной на каждый блок этапа 2 (`corner_ranges`): фейд 12 кадров только в начале и в
  конце ролика, на склейках жёсткий стык (дальше метка вшита в видео этапа 1).
* **Финальная карточка** (`overlays2.render_end_card2`): затемнение, заголовок, акцентная черта, списки и
  чип — как `render_end_card` этапа 1 (те же шрифты, кегли, цвета). Между заголовком и списком — схема
  потока: `END_CARD["flow"]` (7 шагов; скруглённые блоки с номером в оранжевом кружке, оранжевые стрелки,
  подписи в 1–2 строки, кегль подбирается автоматически 26…20 px, разделитель « · » не переносится).
  Ниже — `kpis` (маркированный список, ширина переноса 1600 px, двухстрочный пункт предпочтительно
  переносится после «:» / «,»), затем `cta` (оранжевый чип) и `footer`. Если текст не помещается над
  подвалом, рендер выдаёт ошибку.
* Цвета/отступы, как и в этапе 1, можно переопределить ключом `style` в раскадровке.

Быстрая проверка вёрстки без ffmpeg:

```python
import sys, json; sys.path.insert(0, "stage2_logistics/post")
import overlays2; from PIL import Image
sb = json.load(open("stage2_logistics/post/storyboard2.json", encoding="utf-8"))
ovs = overlays2.render_all2(sb, "stage2_logistics/out/ov_tmp")
overlays2.preview_frame2(Image.new("RGB", (1920, 1080), (90, 110, 130)), ovs, 2120).save("end.png")
```

## Звук

`audio2.py` строит дорожку на всю длину ролика (48 кГц, стерео, 16 бит, детерминированно — `audio.seed`,
у каждого слоя свой генератор). Интервалы берутся из `storyboard2.json → audio`, уже переведённые в
выходные кадры генератором раскадровки:

* **этап 1 внутри сегментов s1** — `weld_intervals` / `servo_intervals` из `demo_video/post/storyboard.json`,
  пропущенные через `edl.map_intervals(..., src="s1")`; туда же добавлена хореография этапа 1, видимая в
  планах этапа 2 (например, возврат сварочного робота в S2_10_done = движение 931–1060 этапа 1). Синтез —
  `audio.servo` (−27 dBFS) и `audio.weld` (дуга −20 dBFS, фон сети −32 dBFS) без изменений.
* **фон цеха** — `audio.ambience` (−32 dBFS) одним куском на весь ролик, без разрывов на склейках.
* **слои этапа 2** (`AUDIO_LAYERS` в `storyboard2.py`) — интервалы сцены из `edl.json → intervals`,
  пропущенные через `edl.map_intervals(..., src="s2")`. Каждый кусок хранится как
  `[out0, out1, real_start, real_end]`: 0 означает, что интервал обрезан монтажной склейкой — там не
  звучат щелчки/удары, а движение, продолжающееся через склейку, склеивается в одно.

| слой | вид интервалов | звук | уровень |
|---|---|---|---|
| handler, tack_robot, positioner, qc_axis | `handler`, `tack`, `positioner`, `qc_move` | `audio.servo`, транспонированный (`pitch` 0,8 / 1,45 / 0,7 / 1,8) | −28 / −30 / −29 / −33 |
| tack_arc | `tack_arc` | короткая дуга прихватки: треск 1,2–7 кГц + шипение, «чпок» зажигания + звон 2,2 кГц | −27 |
| clamp, stud, gripper | `clamp`, `stud`, `gripper` | пневматика: шипение клапана, в конце хода — удар цилиндра и выхлоп (захват — мягче) | −29 / −29 / −33 |
| conveyor | `conveyor` | рольганг: низкий гул, 100/200 Гц привода, щелчки роликов ~7/с | −30 |
| marker | `marker` | лазерный маркер: свист гальвосканера 1,8–3,4 кГц, гудение драйвера, вытяжка | −31 |
| scan | `scan` | профилометр: мягкие сигналы 1,6 кГц каждые 0,5 с + шорох | −32 |
| agv | `agv` | предупредительный зуммер AGV 1,9 кГц (0,18 с / 0,8 с) + привод | −31 |
| chime | событие `qc_ok` | двухтональный сигнал «OK» (ми6 → ля6) | −24 |

Уровни — RMS внутри собственных интервалов слоя до общей нормализации микса к пику −3 dBFS (как в этапе 1;
сейчас нормализация даёт +4 дБ ко всем слоям). Новые слои не громче сервоприводов, громче только сигнал OK.
Менять: уровни/`pitch`/`pan` — в `AUDIO_LAYERS`, `CHIME`, `AUDIO_LEVELS` (`storyboard2.py`, затем
перегенерировать раскадровку); характер звука — функции `*_layer` в `audio2.py`; новый вид интервалов —
запись в `AUDIO_LAYERS` с одним из типов `servo, tack_arc, pneumatic, conveyor, marker, scan, agv`.
`python3 stage2_logistics/post/audio2.py --report` печатает фактические уровни всех слоёв.

В текущем монтаже интервалы `conveyor` (2834–2950, 3143–3243 кадры сцены) не попадают ни в один план, поэтому
рольганг не слышен; слой зазвучит сам, если в монтаж вернуть план S2_13_convey.

## Тест

`python3 stage2_logistics/tests/t_post2.py [--threads 2] [--skip-compose]`:

1. раскадровка: `storyboard2.json` совпадает с генератором, `storyboard2.check` без замечаний, отдельно —
   нет пересечений, промежутки ≥ 4 кадров, длительности больше двух фейдов, подписи ≥ 28 кадров, ничего над
   сегментами этапа 1, по подписи на каждый план с `caption`, угловые метки по блокам с правильными фейдами;
2. звук: длина = кадры/24, пик −3 dBFS, новые слои не громче сервоприводов, сигнал OK чуть громче, дуга
   этапа 1 — самый громкий слой; WAV сохраняется в `out/post_test_soundtrack.wav`;
3. синтетические кадры: каждый 6-й кадр сцены (1, 7, 13, …) каждого плана, 640×360, с номером кадра, именем
   плана и 12-битным штрихкодом номера → `out/post_test_frames/`; сборка `compose2 --preview` →
   `out/post_test_preview.mp4`;
4. ffprobe: длительность = 2154/24 с (±1 кадр), 2154 кадра, h264 1920×1080 24 fps yuv420p, AAC 48 кГц стерео;
5. склейки: первый и последний кадр каждого сегмента этапа 1 против кадров f0/f1 видео этапа 1 (PSNR > 30 дБ
   и лучше соседних кадров);
6. контент этапа 2: штрихкод в 58 кадрах всех 15 планов совпадает с ожидаемым удерживаемым кадром сцены;
7. контактный лист `out/post_check_sheet.jpg` (титул, все подписи, кадры по обе стороны каждой склейки,
   финальная карточка) и крупные кадры `out/post_check_endcard.png`, `out/post_check_caption.png`.
