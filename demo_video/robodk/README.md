# Ячейка сварки трубных спулов в RoboDK

Папка содержит скрипт `build_station.py`, который строит в RoboDK ту же ячейку, что и Blender-демо
(`demo_video/`): ABB IRB 4600-40/2.55 на линейном треке, 2-осевой позиционер, спул DN250
(фланец – отвод – труба), два кольцевых шва и полную хореографию сварки из `cell/animation.py` /
`post/storyboard.json` (46 с, 1104 кадра).

## Что нужно

* RoboDK 5.6.5 или новее на вашем ПК (скрипт использует `AddShape` с несколькими цветными телами и
  `AddCurve` — они требуют сборку 23742+).
* Робот **ABB IRB 4600-40/2.55** в локальной библиотеке RoboDK (`File > Open online library`, найти
  `IRB 4600-40/2.55`, нажать *Download*). Скрипт ищет файл `*IRB*4600*40*2.55*.robot` в папке
  библиотеки (`RDK.getParam("PATH_LIBRARY")`, обычно `C:/RoboDK/Library`). Если не найдёт — выведет
  путь к библиотеке и откроет диалог выбора `.robot` файла.
* Python-пакет `robodk` (идёт в комплекте с RoboDK; для внешнего python: `pip install robodk`).
* Файл `spool.stl` рядом со скриптом (уже лежит в папке; как перегенерировать — ниже).

## Как запустить

Вариант 1 — из RoboDK: `File > Open` → выбрать `build_station.py` (он добавится в станцию как
Python-программа) → правой кнопкой → *Run Python script*.

Вариант 2 — из терминала при запущенном RoboDK:

    cd demo_video/robodk
    python build_station.py

Скрипт создаёт **новую станцию** `PipeSpool_WeldCell` (и сохраняет её в `PipeSpool_WeldCell.rdk`
рядом со скриптом, флаг `SAVE_RDK`). Повторный запуск создаёт ещё одну станцию — старую можно закрыть.

## Компоновка (мм, как в `cell/layout.py`)

Мировая СК: Z вверх, X — к роботу, Y — вдоль трека. Позиционер стоит в начале координат, трек — при x = 2000.

* **Ось наклона позиционера параллельна треку (мировая X)** и проходит через (0, 0, 1350); башни подшипников
  при x = ±680. Наклон 0 — планшайба смотрит вверх (загрузка); **наклон +90° — планшайба смотрит в +Y**, её центр
  в (0, 250, 1350); наклон −90° — смотрит в −Y. Индексация на 180° — это переворот наклона +90 → −90 «через верх».
* Спул стоит на 30 мм над планшайбой (кольцо-адаптер). В локальной СК спула фланец лежит в плоскости z = 0,
  ось +Z, отвод уходит в +X, труба — вдоль +X от центра шва B.
* При наклоне +90 и угле планшайбы 360° (= 0°) труба лежит вдоль +X (к роботу): шов A — окружность в плоскости
  y = 380 с центром (0, 380, 1350) (верхняя точка (0, 380, 1487)); шов B — окружность в плоскости x = 381 с центром
  (381, 761, 1350), ось X. После переворота (наклон −90) центр шва B — (381, −761, 1350).
* Робот: база на каретке трека на высоте 450, развёрнут на 180° (рука смотрит на позиционер). Дом трека y = −1900,
  домашние суставы (0, −31.5, 54.4, 0, 65.9, 0)° — вылет назад, предплечье вверх, горелка вертикально над треком.
* Станции трека: шов A — y = +200; секторы 1–2 шва B — y = +761; секторы 3–4 — y = −761.
* **Транзитная поза**: горелка вертикально вниз, TCP в точке (1350, y трека, 2050) над треком — вне зоны, которую
  заметает изделие при повороте планшайбы и перевороте позиционера. Сохраняется как **суставная** цель `Transit`
  (одна и та же конфигурация руки на любой станции трека).

## Что создаётся

| Элемент | Описание |
|---|---|
| `Cell` | опорная система координат в начале станции (мм, Z вверх, X к роботу, Y вдоль трека) |
| `Linear track Y` | 1-осевой механизм (BuildMechanism, 1T) вдоль Y при x = 2000, ход −2000…+2000, дом −1900 |
| `ABB IRB 4600-40/2.55` | из библиотеки; базовая СК посажена на каретку трека (высота 450, разворот 180°) |
| `MIG torch` | инструмент: STL кронштейна/шеи/головы с изгибом 45°, TCP на конце вылета проволоки |
| `Positioner tilt` / `Positioner faceplate` | 2-осевой позиционер как два сцепленных 1R-механизма: наклон вокруг мировой X через (0,0,1350) (пределы ±120°) и вращение планшайбы (250 мм над осью наклона); наклон +90° = планшайба смотрит в +Y |
| `Spool DN250` | спул из `spool.stl`, посажен на 30 мм над планшайбой (фланец на планшайбе) |
| `Seam A curve`, `Seam B curve` | кольцевые швы как кривые (точки + внешние нормали), едут вместе со спулом |
| `Seam A/B curve follow` | проекты *Curve Follow* (Utilities) для каждого шва — альтернатива явным целям |
| `Robot_*`, `Track_*`, `Pos_*` | подпрограммы: явные списки целей MoveL для швов (горелка по нормали, угол «углом вперёд» 10°, шаг ~4°), перемещения трека и позиционера |
| `DemoCycle` | главная программа — вся хореография ролика с переключением камер |
| `ArcOn`, `ArcOff` | макросы: включают/выключают «наплавку» (Spray_Add — валик проецируется на спул) |
| `View_C1_wide` … `View_C9_final` | 12 макросов: ставят 3D-вид в положение камеры соответствующего кадра раскадровки (`SHOTS` из `cell/animation.py`) |
| `Cameras/Cam_*` | системы координат камер (Z = направление взгляда); при `OPEN_2D_CAMERAS = True` открываются как симулированные 2D-камеры |
| `Cell dressing` | ограждение с дверью и световой завесой, шкаф IRC5, сварочный источник, бочка с проволокой, станция чистки горелки, вытяжной зонт, паллеты, красные колонны цеха, кран-балка, бетонная плита |

Хореография `DemoCycle` (как в `cell/animation.py` и `post/storyboard.json`; в RoboDK оси движутся последовательно,
в ролике часть движений совмещена):

1. `View_C1_wide`, `Cell_Home` — робот в доме, трек −1900, наклон 0, планшайба −20°.
2. `View_C2_setup`: наклон 0 → +90 (`Pos_TiltUp`), трек в y = +200 (`Track_ToA`), робот дом → транзит → 150 мм над
   верхней точкой шва A (`Robot_ApproachA`).
3. `View_C3a_laser`: лазерный поиск стыка (`Robot_ScanA`) — качание ±60 мм **вдоль оси шва (мировая Y)** на высоте 35 мм.
4. `View_C3b_closeA`, **шов A** (`Robot_WeldA`): горелка неподвижна в верхней точке (0, 380, 1487), планшайба
   поворачивает спул с −20° до +360° (380°; `Pos_RotSeamA_1` до 86°, смена вида `View_C4_midA`, `Pos_RotSeamA_2`),
   дуга включена. Труба оказывается вдоль +X. Подъём на 150 мм и MoveJ в транзитную позу.
5. `View_C5_reposition`: трек в y = +761 (`Track_ToB1`), радиальный подход 120 мм к началу сектора 1 (`Robot_ApproachB1`).
6. `View_C6a_closeB1`, **сектор 1** (`Robot_WeldB_S1`): от 12 часов в сторону −Y, −4…+94°, радиальный отход 120 мм,
   MoveJ в точку «1:30» с отходом 160 мм. `View_C6b_closeB1`, **сектор 2** (`Robot_WeldB_S2`): подход 120 мм,
   от 12 часов в сторону +Y, отход 150 мм, MoveJ в транзит.
7. `View_C7_index`: переворот наклона +90 → −90 через верх (`Pos_Index180`; труба остаётся вдоль +X, несваренная
   половина шва B снова сверху), трек в y = −761 (`Track_ToB2`), подход к сектору 3 (`Robot_ApproachB2`).
8. `View_C8a_closeB2` / `View_C8b_closeB2`: **секторы 3 и 4** (`Robot_WeldB_S3`, `Robot_WeldB_S4`) по той же схеме,
   в конце — транзит.
9. `View_C9_final`: робот в дом, трек в дом (−1900), наклон −90 → 0.

Скорости: сварка 10 мм/с, воздушные переходы 500 мм/с (60°/с в суставах), трек 500 мм/с, наклон/индексация
позиционера 20°/с, вращение планшайбы на шве A 10°/с (константы в начале файла; для «честных» 10 мм/с
на радиусе 136 мм поставьте `POS_WELD_DEGS = 4.2`).

## Запись видео

В API RoboDK (robolink.py, `Robolink.Command`) команда записи видео не документирована, поэтому запись
делается вручную:

1. Поставьте 3D-вид (макрос `View_C1_wide` уже вызывается в начале `DemoCycle`).
2. Включите след горелки, если нужен жёлтый путь: `Tools > Trace` (Alt+T). Валик шва рисуется макросом `ArcOn` автоматически.
3. `Tools > Record` (запись экрана 3D-вида; там же выбирается папка/имя файла). Скорость симуляции —
   ползунок в панели или `RDK.setSimulationSpeed(1)` (скрипт ставит 1× — реальное время).
4. Дважды кликните `DemoCycle` (или правой кнопкой → *Run*). По окончании снова `Tools > Record`,
   чтобы остановить и сохранить видео.

Альтернатива для монтажа по кадрам: включить `OPEN_2D_CAMERAS = True` и снимать кадры камер
`RDK.Cam2D_Snapshot(...)` из своего скрипта.

## Что можно настроить

* **Другой робот**: `ROBOT_LIBRARY_GLOBS` — шаблоны поиска `.robot`; `ROBOT_Q_HOME` — домашняя поза (градусы,
  соглашение ABB). Базу робота скрипт ставит сам: `robot_base_pose_world()`.
* **Трек/позиционер из библиотеки**: `TRACK_LIBRARY_GLOB`, `POSITIONER_LIBRARY_GLOB` (шаблон в папке
  библиотеки). Кинематика библиотечных механизмов может отличаться (направление оси, положение фланца),
  поэтому по умолчанию оба строятся `BuildMechanism` точно по `cell/layout.py`. Если после сборки хотите
  синхронизировать трек с роботом как внешнюю ось (единый список суставов в программах), сделайте это в
  GUI: правой кнопкой по роботу → *Synchronize external axes* — из API это не документировано.
* **Геометрия механизмов**: тела позиционера и трека задаются в мировых мм в том положении, в котором механизм
  находится при `joints_build` (так работает GUI *Utilities > Model mechanism*, а `base` задаёт только положение
  оси). Если в вашей версии RoboDK собранный позиционер/трек окажется повёрнутым, поставьте
  `MECH_GEOMETRY_IN_BASE_FRAME = True` — тела будут переданы относительно базовой СК механизма.
* **Швы**: `SECTOR_POINTS` (целей на сектор), `SECTOR_A0`/`SECTOR_A1` (−4…+94°), `WEAVE_AMPL_MM`/`WEAVE_FREQ_HZ`
  (колебания вдоль оси шва, 0 = выкл.), `PUSH_ANGLE_DEG`, `LIFT_APPROACH` (радиальный подход/отход 120),
  `LIFT_PARK` (150), `VIA_RETRACT`/`VIA_ANGLE` (точка возврата «1:30», 160 мм), `SCAN_HEIGHT`/`SCAN_HALF`,
  `TRANSIT_TCP`. Программа `Robot_WeldA_MoveL` — вариант шва A, когда изделие стоит, а горелка обходит стык
  (в `DemoCycle` не вызывается).
* **Камеры**: список `SHOTS` (имя, кадры, позиция, точка прицеливания, фокус — стартовые положения камер
  `cell/animation.py`). Макросы `View_*` используют `setViewPose` в соглашении OpenGL (камера смотрит вдоль −Z,
  Y вверх). Если вид окажется «спиной» к ячейке — поставьте `VIEW_OPENGL = False` и перезапустите.
* **Спул**: перегенерировать `spool.stl` из Blender-модели (мм, локальная СК спула — задняя плоскость
  фланца z = 0, ось +Z, отвод в +X):

      cd demo_video
      python3 -c 'import bpy,sys; sys.path.insert(0,"."); from cell import spool; bpy.ops.wm.read_factory_settings(use_empty=True); s=spool.build(); spool.export_stl(s, "robodk/spool.stl")'

    python3 tests/t_robodk_math.py        # чистая математика + полная сборка на mock-Robolink;

## Ограничения

* На этой машине RoboDK нет, поэтому скрипт проверен только на «заглушке» API (все вызовы сверены с
  исходниками `robolink.py`/`robomath.py` пакета `robodk` 6.0.2). Первый запуск в настоящем RoboDK может
  потребовать мелкой доводки: конфигурация IK для отдельных целей (программы пишут в консоль долю
  достижимых точек после `Update`), знак ориентации «путь→инструмент» в проектах Curve Follow, соглашение
  о геометрии `BuildMechanism` (см. `MECH_GEOMETRY_IN_BASE_FRAME`).
* Цели швов заданы в СК `Cell` (мировой); робот стоит на несинхронизированном треке, поэтому RoboDK решает
  IK в момент выполнения с текущим положением каретки — программы `Track_*` всегда вызываются до соответствующих
  `Robot_*`.
* Позиционер и трек — упрощённые «коробочные» геометрии; робот берётся из библиотеки RoboDK.
* Лазерный поиск, дуга и вытяжка симулируются только цифровыми выходами `LaserScan`/`WeldArc` и
  макросом `ArcOn` (валик); искры/дым в RoboDK не воспроизводятся.
